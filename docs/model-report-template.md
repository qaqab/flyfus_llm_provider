# 模型测试结果文档模板

每个模型单独返回一份 Markdown 文档。文档只写实际测试结果，不写宣传能力。

最重要的规则：参数请求不报错，不代表参数有效。只有参数设置前后出现稳定、可重复的实际变化，才标记为支持。

## 需要返回的信息

### 基本信息

- 模型 ID；
- 测试日期；
- 总结论：可用、部分可用或不可用；
- 主要限制和已知问题。

### 输入和输出上限

必须实际测试并返回：

- 总上下文长度；
- 最大输入 token；
- 测最大输入时预留了多少输出 token；
- 最大输出参数值；
- 实际成功生成过的最大输出 token；
- 最大可见正文 token；
- 思考 token 是否占用输出上限；
- 超出输入或输出上限时的错误表现。

最大输入不能只看模型说明。使用带随机尾部校验码的长文本逐步增加长度，模型能够准确返回尾部校验码才算读取成功。

最大输出不能只把一个大数传给 `max_tokens`。必须要求模型持续生成足够长的可校验内容，并根据返回的 usage 或实际 token
计数确认真正生成的长度。

结果至少写清楚：

| 项目 | 实测结果 | 说明 |
|---|---:|---|
| 总上下文 | | |
| 最大输入 | | 输出预留： |
| 最大输出参数 | | |
| 最大实际输出 | | |
| 最大可见正文 | | |
| 思考是否占输出额度 | 是/否/无法确认 | |

### 参数生效判定

- `temperature`：低值和高值分别重复生成，输出随机性应有稳定差异；
- `top_p`、`top_k`：不同值下输出选择范围或多样性应有稳定差异；
- `presence_penalty`：设置前后，已出现内容再次出现的倾向应有差异；
- `frequency_penalty`：设置前后，重复词或重复句比例应有差异；
- `max_tokens`：输出应在对应长度附近停止，或明确返回长度结束原因；
- `seed`：相同 seed 多次输出应可复现，不同 seed 应有差异；
- 布尔开关：true 和 false 必须出现实际行为差异；
- 枚举档位：每个档位都要测试，不能只测试其中一个。

采样和惩罚参数没有观察到稳定差异时，写“请求接受，但效果未确认”，不要写“支持”。

## 参数组合与冲突

参数单独有效，不代表一起使用时有效。所有准备提供给用户的参数都必须做组合测试。

### 测试顺序

1. 不传任何可选参数，记录模型默认行为；
2. 每个参数单独测试；
3. 所有参数两两组合测试；
4. 对高风险组合测试最小值、默认值和最大值；
5. 把实际使用时会发送的全部参数放在同一个请求里测试；
6. 对包含三个以上参数的常用组合重复测试；
7. 分别测试参数缺失、显式传默认值和传 null 的区别；
8. 流式和非流式分别测试常用组合。

参数较多时，不要求遍历所有数值的笛卡尔积，但必须保证每一对参数至少共同出现一次，并覆盖关键边界值。

### 必测高风险组合

- `temperature + top_p`；
- `temperature + top_k`；
- `top_p + top_k`；
- `presence_penalty + frequency_penalty`；
- `seed + temperature`；
- `max_tokens + enable_thinking`；
- `max_tokens + thinking_budget`；
- `max_tokens + reasoning_effort`；
- `enable_thinking + thinking_budget`；
- `enable_thinking + reasoning_effort`；
- `thinking_budget + reasoning_effort`；
- 参数与流式输出；
- 参数与图片输入；
- 参数与文件输入。

模型存在其他私有参数时，也必须加入两两组合测试。

### 冲突类型

组合测试需要明确属于哪种情况：

- **直接报错**：参数单独可用，组合后返回 4xx、5xx 或协议错误；
- **互相覆盖**：两个参数都被接受，但其中一个优先，另一个不再生效；
- **静默忽略**：没有报错，但组合后某个参数被忽略；
- **范围变化**：单独使用时的最大值，在组合后不再可用；
- **行为冲突**：请求成功，但输出同时违反两个参数中的一个；
- **不稳定**：相同组合有时成功、有时失败；
- **无冲突**：两个参数都保持各自已验证的效果。

不能因为组合请求返回 200 就写“无冲突”。必须再次验证两个参数各自的效果仍然存在。

|---|---|---|---|---|---|---|---|---|
| temperature | top_p | | | | | | | |
| presence_penalty | frequency_penalty | | | | | | | |
| max_tokens | thinking_budget | | | | | | | |
| enable_thinking | reasoning_effort | | | | | | | |
| 其他组合 | | | | | | | | |

最终报告还要单独列出：

- 可以安全同时发送的参数；
- 不能同时发送的参数；
- 必须二选一的参数；
- 有优先级关系的参数；
- 组合后需要缩小的参数范围；
- 推荐的完整默认参数组合。

## 工具调用

只需要测试两个核心能力：

1. 模型能否调用一个外部工具，并在回传工具结果后生成正确答案；
2. 同一个请求同时提供外部工具和模型内置工具时，是否可以正常使用，是否报错或互相冲突。

内置工具包括模型服务自带的联网搜索、代码执行等能力，不包括客户端自己实现的 function tool。

| 项目 | 结果 | 说明 |
|---|---|---|
| 外部工具调用 | 支持/不支持/不稳定 | 工具名称、参数和结果回传是否正确 |
| 外部工具 + 内置工具 | 支持/不支持/冲突/未测试 | 是否能在同一请求中共同使用 |

只返回 tool call，但没有完成工具结果回传和最终回答，不能写成完整支持。

## 联网搜索

- 是否返回正确的新信息；
- 是否返回可访问的来源链接；
- 搜索开关 true 和 false 是否有实际差异；

## 文件能力

至少测试：

- TXT；
- PDF 文本文件；

## 已知问题

所有失败和不稳定项都要列出，不能只写支持项：

- 哪个参数被忽略；
- 哪种输入返回 200 但没有实际读取；
- 哪些组合会报错；
- 哪些请求容易空响应或提前结束；
- 哪些结论还没有测试清楚。
